## 2. 行為規範

- **不阻塞**：AI 推理、事件寫入、警報推播均不得運行於 UI/解碼執行緒；監看幀渲染只做最後一次取樣結果的拷貝更新。
- **AI 疊加**：
  - 僅於「AI 疊加」開關啟用且畫面格有資料流時繪製。
  - 座標為 0..1 正規化，繪製時乘以該格顯示區解析度；M245：影像為 `UniformToFill`，縮放改採與影像一致的「填滿」比例（取較大者），避免 4:3 來源的框貼在錯的位置。
  - 疊加框使用該格「最新推理結果」；幀到達時以當格畫面對齊繪製（滯後物件位置可容忍至推理周期內）。
  - 類別色彩：person＝番茄紅、car/bus/truck/motorcycle/bicycle＝水藍；他人類別以灰框。
  - label（類別＋confidence）僅在單一畫面佈局顯示；四路只畫框。
  - **每格 AI 策略（M14）**：多格佈局僅「選中格」推理並繪製疊加；單格展開時取消間隔降為 200ms；非選中格停用取樣（零 CPU）。
- **布點對應**：Cell→Channel 對應由 ChannelManager 連線次序決定；重連後保持一致。
- **佈局切換**：格子為程式動態建立（`UniformGrid`，列×欄由 `MonitorGrid.Fit` 依監看區比例決定，每格＝影像＋AI 疊加＋狀態文字＋右鍵選單），切換即重建；已連線的 cell 對應（`_cellChannel`）與既得位圖保留，重建後自動套回；監看區尺寸變動會重新計算列×欄與置中外框。
- **佈局選項（M259）**：頂欄佈局下拉固定為平方數 **1／4／9／16／25／36**（`LayoutCellCounts`，`MaxLayoutIndex=5`），12 分割已依使用者回饋移除。
- **佈局記憶**：切佈局時以 JSON 寫入資料根 `ui.json`（鍵 `layout`，0..5）；下次啟動套用（越界以 `Math.Clamp` 夾到最近合法佈局，不會打回 1×1）。
- **視窗全螢幕（M249）**：主視窗以無邊框滿版啟動；進入時先記下當下的 `WindowStyle`／`ResizeMode`／`WindowState`，退出時還原（從一般視窗按進全螢幕再退出會回到原尺寸）。Esc 在「非單格展開」時退出全螢幕。
- **視窗層級（M254／M257）**：子視窗（設定中心等，`Owner`＝主視窗）關閉後由 `BringToFront()`（`Show`／還原最小化／`Activate`）帶回前景。症狀：無邊框全螢幕的主視窗在子視窗關閉後不一定被系統帶回，最小化時 `OnStateChanged` 又會 `Hide()`，於是「設定關掉後找不到監控中心」。**不再置頂（M257）**：先前的主視窗 `Topmost="True"` 與 `BringToFront` 內的 `Topmost = true` 已移除，否則監控中心會一直蓋在設定中心等子視窗之上；現在只帶回前景、不強制保持在上層。由 `UiWiringContractTests` 守住。
- **關閉選擇（M251）**：關閉主視窗（頂欄「離開」、Alt+F4、工作列關閉）一律先跳 `ExitChoiceWindow`「最小化到系統匣／結束 HeliVMS／取消」，不再靜默收進系統匣；系統匣選單「結束 HeliVMS」與命令列匯出等已明示路徑直接結束。因主視窗無標題列，頂欄提供「離開」按鈕作為關閉入口。
- **職責重整（M252／M253）**：監控中心只保留監看本體——頂列＝分割布局＋事件／回放／地圖＋全螢幕／設定／離開，沒有左側面板、沒有手動連線／錄影；原「相機管理／頻道管理」與「更多工具」面板（排程、偵測、巡航、PTZ、切流、音訊、IO、匯出、通知、規則、稽核、法律保留、報表、摘要、法證檢索、系統健康、警報、智慧牆、POS、邊緣補抓、備援）全部移入設定中心「功能」頁，依類別分組，管理動作在 handler 內以 `RequireAdmin()` 硬擋、授權動作以 `LicenseUiGate.Allows` 綁同一旗標。PTZ 於設定頁以頻道下拉 (`PtzChannelCombo`) 選擇目標。
- **頻道異動即時生效（M258）**：子視窗（設定中心→攝影機／頻道管理）關閉後，`OpenChild` 的 `Closed` 會呼叫 `ReloadChannelsIfChangedAsync()`，以 `ChannelSignature` 比對清單，有新增／刪除／修改才 `RefreshChannelList()` 並重新連線（`AutoStartMonitoringAsync`），新頻道立即出現在監看區、不必重啟程式；無變動（例如關閉事件中心）不重連，避免錄影短暫中斷。空清單則 `DisconnectAllAsync()`。提醒：自設定中心開出的子視窗要等設定中心關閉才會觸發。
- **開機全自動（M253）**：`AutoStartMonitoringAsync()` 連線全部已設定頻道（`ConnectAsync(_channelList, 0, count)`；超出目前佈局格數的頻道仍背景串流、不入格），並呼叫 `RecordingScheduler.ReconcileAsync()` 立即開始全時錄影（頻道預設 `RecordingMode.Always`），不必等第一次週期輪詢；授權／排程閘門仍由排程器把關。自動啟動失敗不崩潰，後續週期會再嘗試。由 `AutoStartMonitoringContractTests` 守住接線。
- **警報**：同一頻道在同 3 秒內之相同事件類型節流為一筆；推播格式 `HH:mm:ss 頻道名｜事件詳情`。
- **未確認計數**：週期 15 秒自 alarm_events 統計 unacknowledged；點擊「事件」開啟事件中心時即時重新統計。
- **多語系（M57 §14.7 垂直切片）**：主視窗所有可見文字改走 `Localizer.T`（繁中／簡中／EN 三語，集中於 `I18n.cs`），`MainWindow.xaml` 不再硬編中文、文字一律留空由 `ApplyI18n()` 指派；設定中心切換語言時 `RefreshTitle()` 會重套全部文字。由 `WpfI18nContractTests` 的 `MainWindow` 棘輪守住（XAML 禁中文、載入須呼叫 `ApplyI18n`、引用鍵須三語齊備）。

## 3. 效能規範

| 項目 | 目標 |
| --- | --- |
| 推理不阻塞監看 | < 方案：獨立佇列＋worker，取樣 ≥ 400ms |
| 監看渲染 | 單幀拷貝 ≤ 66ms（15fps） |
| AI 疊加繪製 | 每格 ≤ 4ms，且僅接收幀事件時觸發 |
| 警報列 | 不需 DB 查詢（除未確認計數週期） |
| 32 路策略（v1.4 M14） | 僅選中/展開格開啟 AI（非選中停用省 CPU）；單格 200ms、≤4路 400ms、≥9路 800ms 降頻；`AiConcurrencyScheduler` 全域限併發（預設 2，`HELIVMS_AI_CONCURRENCY` 可調） |

## 4. 驗收標準
1. 四路同時連線虛擬流，開啟 AI 疊加：人身/車流樣本畫面即時出現對應框與 label。
2. 畫格縮放（視窗 resize／切佈局）後框與影像仍對齊。
3. 警報列出現 AI 偵測與離線/重連訊息。
4. 時間軸無阻塞（錄影持續、UI 可操作）。
5. 全方案建置 0 warning；單元測試覆蓋偵測轉發、count API。
6. E2E `liveoverlay`：RTSP 車流樣本 → 收集偵測流，確認 bbox 於畫內合理性（0≤x+y<1、w/h>0）。
